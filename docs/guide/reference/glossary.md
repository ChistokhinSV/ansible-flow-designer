# Glossary

The words the designer, its commands and this guide use, one word per thing. The designer's labels,
the Command Palette and these pages are checked against the **Not** column. Back to the
[guide](../README.md).

## Writing rules

- **Actions** (commands, menu items, buttons) are in Title Case, as in VS Code's own menus:
  **Tidy Up**, **Add Node Here…**, **Open in Text Editor**. An action that asks for something before
  it acts ends with "…".
- **Messages, descriptions and tooltips** are sentences: "Lay out the whole level again".
- **Port names** are written as in the file: `ok_hosts`, `failed_hosts`, `unreachable`.
- No milestone or decision codes in what users read: no "(M5)", no "decision 3".

## The flow

| Term                  | Meaning                                                                                                                                                   | Not                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| flow                  | the diagram in a `*.flow.yaml` file, and the automation it describes                                                                                      |                        |
| node                  | a box on the canvas: start, end, task, subflow, decision, approval, parallel or join                                                                      | `New node`             |
| step                  | a node that runs something: a task, an approval, or a subflow                                                                                             |                        |
| port                  | where a wire starts or ends on a node; hosts leave a node through one of its output ports                                                                 |                        |
| wire                  | a connection from an output port to the `in` port of the next node: the hosts that left by the port go there                                              |                        |
| open port             | a fail-type port without a wire: its hosts fail in the outcome, and the banner counts it                                                                  |                        |
| open on purpose       | an open port accepted with a reason: its hosts stop in the outcome, and the banner no longer counts it                                                    |                        |
| level                 | what the canvas shows at a time: the top level, or the inside of one subflow                                                                              |                        |
| subflow               | a node that holds its own level; hosts enter through its entry and leave through its ports                                                                |                        |
| rolling subflow       | a subflow whose hosts go through all its steps in batches (Rolling batch), one batch after another                                                        |                        |
| shared subflow        | a subflow copied from another flow, pinned to that flow's version: edited in the source, brought here with Update                                         |                        |
| entry, exit           | where hosts enter a subflow's inside, and the inner port that leaves through one of the subflow's ports                                                   |                        |
| binding               | what a step runs: a module, a role or a playbook, with its parameters                                                                                     | `Bind implementation`  |
| status                | how far a node is: draft, specified, implemented, tested                                                                                                  |                        |
| purpose               | what a step is for in failure handling: rollback, notify, retry or exclude (format 1 calls it `handler`; it is not an Ansible handler)                    | `Failure handler role` |
| problem               | something the design check found, in the banner and the Problems panel                                                                                    |                        |
| finding               | something a lens found, in the lens's panel                                                                                                               |                        |
| lens                  | a view over the whole flow (Inventory, Access, Data, Timing, Code, Changes) with chips on the nodes and findings                                          |                        |
| drift                 | a difference between the design and the code it runs, shown in Code mode                                                                                  |                        |
| format                | the version of the file's layout (`schema_version`): 2 for new flows; **Upgrade Flow Format** moves a 1 to 2                                              |                        |
| annotation            | a note, section or text on a level: it explains the flow and never runs; changing it changes no version                                                   |                        |
| note                  | a sticky annotation; a note on a node is tied to it and moves with it                                                                                     | `Sticky note`          |
| section               | a titled annotation behind steps; moving it moves what is inside                                                                                          | `Group box`            |
| text                  | an annotation of words with no background, in three sizes                                                                                                 | `Text label`           |
| task                  | a step that runs one module, role or playbook (or, while unbound, a TODO message)                                                                         |                        |
| decision              | a node that sends each host to `true` or `false` on a condition; also the record Accept with Reason… writes (`decisions:` in the file)                    |                        |
| approval              | a node that waits for a person: `approved` or `rejected`, and `timeout` when no one answers                                                               |                        |
| parallel, join        | a node that sends every host down each branch, and the node that brings the branches back                                                                 |                        |
| start, end            | where hosts enter a level, and where they leave it; an end has an outcome, success or failed                                                              |                        |
| fail port             | a port for hosts that failed: `failed_hosts`, `unreachable`, `timeout`, `rejected`; each needs a handler or a reason                                      |                        |
| failure pattern       | a ready handler for a fail port, in one undo step: Rollback from Backup, Notify On-Call and Stop, Exclude and Report, Retry, Stop Flow, Escalate Approval |                        |
| intent                | one sentence on what a step does; the skeleton run prints it                                                                                              |                        |
| key                   | a node's name in the file and in the generated code (`check-ntp`), unique on its level                                                                    |                        |
| ID                    | a node's fixed identifier (a ULID); it never changes, so runs and code map back to the node                                                               |                        |
| inputs and outputs    | what a step reads and what it sets for later steps; `from:` says where an input comes from                                                                |                        |
| result                | what a step's module or role returned (`register`), which its outputs can read                                                                            |                        |
| task keywords         | Ansible keywords written on a step's generated task as they are: `when`, `loop`, `ignore_errors`…                                                         |                        |
| generated code        | the playbooks in `generated/`, one play per step, rewritten on every save; never edit them                                                                |                        |
| skeleton run          | `ansible-playbook --check` of the generated code; steps without a binding print TODO                                                                      |                        |
| Ansible environment   | where Ansible runs: an execution environment image (Docker or Podman), WSL, VS Code Remote or a venv                                                      |                        |
| execution environment | a container image with ansible-core and collections (EE)                                                                                                  |                        |
| catalog               | the modules and roles your Ansible environment has, searched from the Binding tab                                                                         |                        |

## Modes and panels

| Term                 | Meaning                                                                                                                                                 | Not                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Design mode          | drawing the flow: nodes, wires, ports, subflows                                                                                                         |                                                                                                               |
| Code mode            | what each step runs and how it stands against the code (drift)                                                                                          | `Implementation mode`                                                                                         |
| Run mode             | the last run on the canvas, read-only                                                                                                                   |                                                                                                               |
| Details              | the docked panel that edits the selected node: General, Binding, Inputs and outputs, Ports, Execution (Code and Run modes add theirs)                   | `Properties…`, `Open properties`, `inspector`, `Inspector`, `properties page`, `Details page`, `summary card` |
| Binding tab          | the Details tab that sets the binding                                                                                                                   | `Implementation tab`                                                                                          |
| fold                 | a line that says what is behind it (More details, More node types, Extra ports, an Execution group); it opens by itself when something inside needs you | `Advanced`, `Show more`                                                                                       |
| Wire panel           | the right panel of a selected wire: which hosts take it, and Insert, Rewire or Disconnect                                                               | `Edge panel`                                                                                                  |
| first-flow checklist | the "Your first flow" card: four things that make a first flow, each with Show Me                                                                       | `Onboarding`, `Tour`                                                                                          |
| Ansible Flows view   | the Activity Bar view that lists the flows in the workspace                                                                                             | `Flow explorer`                                                                                               |
| palette              | the left column in Design mode: node types, failure patterns, annotations, the Legend                                                                   |                                                                                                               |
| canvas               | the middle: one level's nodes, ports and wires                                                                                                          |                                                                                                               |
| banner               | the line over the canvas that counts open fail ports and asks what should happen                                                                        |                                                                                                               |
| Legend               | the "?" popover in the palette: what the port and wire styles mean, and each port                                                                       |                                                                                                               |
| Quick Add            | the dialog that adds a node: its type, title, intent and extra ports                                                                                    |                                                                                                               |
| readiness            | the flow panel's count of steps per status and of open fail ports                                                                                       |                                                                                                               |
| Execution tab        | the Details tab of where, as whom and when a step runs: Targeting, Privilege, Timing, Tags                                                              |                                                                                                               |

## Actions

| Action                               | Does                                                                                                                                                                                           | Not                                                                                                                                                                                |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add Node                             | adds a node (from the palette, a port, or the canvas menu's **Add Node Here…**)                                                                                                                | `Add node`, `Add step`                                                                                                                                                             |
| Tidy Up                              | lays out the open level again                                                                                                                                                                  | `Tidy up`, `Tidy Up Layout`, `Auto-layout`                                                                                                                                         |
| Open in Text Editor                  | opens the flow file, or a node's place in it, in VS Code's text editor                                                                                                                         | `Open as text`, `Open as Text`, `Show as text`, `Show in text`                                                                                                                     |
| Check Flow                           | checks the design, then the generated code in your Ansible environment                                                                                                                         | `Validate design`, `Validate Design`, `Check Generated Code`                                                                                                                       |
| Generate Code                        | writes the playbooks in `generated/`                                                                                                                                                           | `Generate Playbook`                                                                                                                                                                |
| Peek Code                            | opens a step's play in its generated file, beside the designer                                                                                                                                 |                                                                                                                                                                                    |
| Show Me                              | on the first-flow checklist: does the item, or opens where it is done                                                                                                                          |                                                                                                                                                                                    |
| Other Choices                        | on the banner: the open port's whole menu                                                                                                                                                      |                                                                                                                                                                                    |
| Accept with Reason…                  | records why something stays as it is: an open port (open on purpose), drift, a lens finding, a warning (format 2)                                                                              | `Leave open on purpose…`, `Leave open on purpose`, `leave it open on purpose`, `Mark expected`, `Mark as expected`, `Ignore…`                                                      |
| Reopen                               | takes back an Accept with Reason…                                                                                                                                                              | `Stop ignoring`                                                                                                                                                                    |
| Notify On-Call and Stop              | the failure pattern that adds a notify handler and ends the hosts as stopped                                                                                                                   | `Notify on-call and stop`                                                                                                                                                          |
| Stop Flow                            | the failure pattern that only wires the port to an end node: the hosts end as stopped                                                                                                          | `Stop flow`                                                                                                                                                                        |
| Re-sync from Git                     | compiles the code in your environment and compares it with the design                                                                                                                          | `Resync`, `Re-sync from git`                                                                                                                                                       |
| Set Up Ansible Environment…          | sets where Ansible runs: a container image (Docker or Podman) or WSL                                                                                                                           | `Configure environment`                                                                                                                                                            |
| Run as Skeleton                      | runs the flow in check mode; steps without a binding run as TODO messages                                                                                                                      | `dry run`, `Run as skeleton`                                                                                                                                                       |
| Run for Real…                        | runs the flow for real, after a confirmation                                                                                                                                                   | `Run for real…`                                                                                                                                                                    |
| Stop Run                             | ends the local run, or cancels the job or workflow in AWX                                                                                                                                      |                                                                                                                                                                                    |
| Launch in AWX                        | runs the flow as its AWX job template or workflow                                                                                                                                              |                                                                                                                                                                                    |
| Import AWX Workflow or Job Template… | turns a workflow or job template, from AWX or an `awx export` file, into a new flow                                                                                                            | `Import from AWX`                                                                                                                                                                  |
| canvas and port menus                | Title Case like every action: Open Subflow, Peek Code, Fit View, Select All, Paste Here, Up to Parent, Add Next Node, Insert Node on This Wire, Extract into Subflow…, Rewire to Another Node… | `Open subflow`, `Peek code`, `Fit view`, `Select all`, `Paste here`, `Up to parent`, `Add next node`, `Insert node on this wire`, `Extract into subflow`, `Rewire to another node` |
